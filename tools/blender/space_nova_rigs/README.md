# Space Nova reusable humanoid rigs

This directory contains a Blender 4.1 `bpy` generator for two standalone,
editable humanoid templates:

- `SpaceNovaMaleRig`
- `SpaceNovaFemaleRig`

Both templates are generated by the same skeleton function and therefore use
the same 51 bone names and parent hierarchy. They are intentionally separate
from the Mara character and the game renderer. Each output `.blend` includes
the editable armature, a lightweight generated mannequin, deterministic skin
weights, and the `SpaceNovaPoseTests` action. Each `.glb` contains the same
rigged test character and action for loading with Three.js `GLTFLoader`.

The same directory also contains an offline Mara fitting stage. It reads the
finished `06_game.glb` and `SpaceNovaFemaleRig.blend`, removes the template
mannequin in the new working scene, infers Mara's actual A-pose landmarks,
refits the existing bones without changing their names or parents, assigns
four-influence linear-blend weights, and exports a separate rigged character.
Neither input is overwritten.

## Coordinate and pose contract

- Blender Z-up, metres, with the character facing Blender `-Y`.
- glTF export uses the standard Y-up conversion expected by Three.js.
- The neutral bind pose is a symmetric 28-degree A-pose.
- `.L` is positive Blender X and `.R` is negative Blender X.
- `root` is the only non-deforming bone. All skin groups correspond exactly
  to deform bones.

`arm_length` means shoulder-to-wrist distance. `leg_length` means hip-to-ankle
distance. Hand and foot sizes are derived from the three head dimensions.

## Headless generation

Run from the repository root with Blender 4.1:

```console
blender --background --python-exit-code 1 \
  --python tools/blender/space_nova_rigs/generate_rigs.py -- \
  --output-dir tools/blender/space_nova_rigs/output
```

Generate one template only:

```console
blender --background --python-exit-code 1 \
  --python tools/blender/space_nova_rigs/generate_rigs.py -- \
  --rig female --output-dir /tmp/space-nova-rigs
```

The generator overwrites only same-named outputs in the selected output
directory. It does not open, import, or modify Mara.

## Anatomical configuration

Provide a partial JSON object to either template. Supported positive
metre-valued keys are `shoulder_width`, `pelvis_width`, `torso_length`,
`arm_length`, `leg_length`, `neck_length`, `head_width`, `head_depth`, and
`head_height`.

```json
{
  "shoulder_width": 0.43,
  "leg_length": 0.88,
  "head_height": 0.235
}
```

```console
blender --background --python-exit-code 1 \
  --python tools/blender/space_nova_rigs/generate_rigs.py -- \
  --female-config /absolute/path/female-proportions.json \
  --output-dir /tmp/space-nova-rigs
```

Invalid, unknown, non-finite, or non-positive values fail generation rather
than producing a malformed rig.

## Headless acceptance validation

Generate first, then run:

```console
blender --background --python-exit-code 1 \
  --python tools/blender/space_nova_rigs/validate_rigs.py -- \
  --output-dir tools/blender/space_nova_rigs/output
```

Validation opens each `.blend`, checks exact bone names/hierarchy, mirrored
left/right rest coordinates and parents, normalized finite vertex weights,
the armature modifier, and deformation at every pose-test frame. It then
starts an empty Blender scene, imports each GLB, and repeats skeleton and skin
checks. Results are written to `output/validation_report.json`.

With the Phoenix asset dependencies installed, verify the files through the
same Three.js loader used by the game:

```console
node tools/blender/space_nova_rigs/validate_three_gltf.mjs \
  tools/blender/space_nova_rigs/output
```

This parses both binary files through `GLTFLoader`, requires one skinned mesh,
51 identical bones, one animation, and normalized four-component glTF skin
weights, and writes `output/three_validation_report.json`. It is a loader-level
test only; it does not add either character to the existing renderer.

Pose-test frames are:

| Frame | Test |
| ---: | --- |
| 1 | neutral A-pose |
| 10 | shoulder rotation |
| 20 | elbow bending |
| 30 | knee bending |
| 40 | hip movement |
| 50 | head turning |

## Mara fitting and validation

From the repository root, run the reproducible headless fit:

```console
blender --background --python-exit-code 1 \
  --python tools/blender/space_nova_rigs/fit_mara.py -- \
  --source ~/ai3d/assets/mara/06_game.glb \
  --female-rig tools/blender/space_nova_rigs/output/SpaceNovaFemaleRig.blend \
  --output-dir tools/blender/space_nova_rigs/output
```

The fitter measures Mara's 1.99 m source bounds and places the pelvis, three
spine sections, shoulders, elbows, wrists, hips, knees, ankles, neck, head,
hands, fingers, feet, and toes in her imported coordinate system. The source
is a single render mesh composed of about 1,001 disconnected topology islands,
so Blender's bone-heat solver cannot produce weights. The pipeline instead
uses reproducible nearest-segment fields, a continuous low-hand/hip-equipment
penalty, topology smoothing, and synchronization across duplicated UV/normal
seam vertices. It caps every vertex at four normalized influences and uses
linear blend skinning to match glTF and Three.js.

Generated files are:

- `output/mara_venn_rigged.blend`
- `output/mara_venn_rigged.glb`
- `output/mara_fit_report.json`
- `output/mara_diagnostics/*.png`

The blend contains the `MaraDeformationTests` action: neutral frame 1,
shoulder frame 10, elbow frame 20, knee frame 30, hip frame 40, and neck frame
50. Validate the editable asset, clean-scene GLB reimport, skin weights,
embedded textures, deformation displacement, and edge stretch with:

```console
blender --background --python-exit-code 1 \
  --python tools/blender/space_nova_rigs/validate_mara.py -- \
  --source ~/ai3d/assets/mara/06_game.glb \
  --output-dir tools/blender/space_nova_rigs/output
```

Then verify the actual game dependency's Three.js 0.187.0 loader, hierarchy,
UVs, embedded images, normalized GPU weights, animation tracks, and finite
runtime skinned bounds:

```console
node tools/blender/space_nova_rigs/validate_mara_three_gltf.mjs \
  tools/blender/space_nova_rigs/output
```

The automated checks pass, but rendered review is deliberately stricter than
the numeric gate. Mara is **not animation-ready**: her fragmented source
topology exposes localized shoulder/inner-elbow seams, hip/knee patch seams,
and imperfect rigid weighting on the belt, holsters, and thigh panels. The
collar/hair boundary also needs a manual neck-turn cleanup. Retopology plus a
manual weight-paint pass is required before production animation sign-off.

The proxy mannequin is a rig engineering fixture, not final character art.
Its disconnected low-poly sections make bone ownership and bad weights easy
to diagnose. Facial rigging and IK controls remain outside this stage.
