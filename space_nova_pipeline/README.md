# Space Nova — Local AI Asset Pipeline (v1)

A working command-line orchestrator for the tools **already installed** on the user's Pop!_OS laptop:

`Qwen-Image (optional) → background removal → Hunyuan3D-2mini → paint-prep mesh → Paint3D → material-preserving Blender optimization → validation report`

**Two real Python scripts are supplied:** `space_nova_pipeline.py` (orchestration) and `space_nova_blender_finalize.py` (preserves existing paint, UVs and materials while reducing triangles).

This is **not** a rigging or animation solution. It also **does not automatically repair missing facial topology, face identity, or texture seams**; these require review of the intermediate GLBs. Full automatic humanoid retopology and rigging are separate projects.

## Install

```bash
mkdir -p ~/ai3d/space_nova_pipeline
unzip ~/Downloads/space_nova_pipeline_v1.zip -d ~/ai3d/space_nova_pipeline
python3 ~/ai3d/space_nova_pipeline/space_nova_pipeline.py --help
```

The script does not install packages or edit your Hunyuan, Paint3D, Blender, Qwen, or Space Nova repositories.

## A. Fastest test: use the Mara mesh AND AI textures you already generated

This tests the final **material-preserving** optimizer without any AI inference:

```bash
python3 ~/ai3d/space_nova_pipeline/space_nova_pipeline.py \
  --name mara_existing \
  --painted-mesh ~/ai3d/outputs/mara_venn_textured_40k.glb \
  --game-faces 15000
```

Output: `~/ai3d/pipeline_runs/mara_existing/06_game.glb`. Import it into Blender and activate **Material Preview** (`Z`, then `M`). The GLB's embedded base-color texture should still be present. Logs and `report.json` are in that run folder.

## B. Repaint Mara using existing geometry (recommended next controlled experiment)

```bash
python3 ~/ai3d/space_nova_pipeline/space_nova_pipeline.py \
  --name mara_repaint \
  --image ~/ai3d/images/mara_venn_cutout.png \
  --shape-mesh ~/ai3d/outputs/mara_venn.glb \
  --paint-faces 40000 \
  --game-faces 15000 \
  --category humanoid \
  --quality fast \
  --stop-after paint
```

Inspect `~/ai3d/pipeline_runs/mara_repaint/05_painted.glb` from front/side/back before final optimization. If happy with the paint stage, rerun the same command with **`--resume`**, changing only `--stop-after game`. The script will reuse previous steps if their inputs/settings are unchanged.

## C. From an existing image, including fresh geometry generation

```bash
python3 ~/ai3d/space_nova_pipeline/space_nova_pipeline.py \
  --name mara_fresh \
  --image ~/ai3d/images/mara_venn_cutout.png \
  --paint-faces 40000 \
  --game-faces 15000 \
  --category humanoid \
  --stop-after shape
```

Inspect `03_shape.glb`; if its face and silhouette are satisfactory, repeat with `--resume --stop-after game`. This runs the full Paint3D and Blender stages. **It will not improve inherently coarse facial geometry** merely by painting at higher resolution.

## D. Optional: from prompt.txt with guarded Qwen generation

**Opt-in only** because Qwen previously froze the laptop. Starts at 384 × 576, 12 steps, disk-backed parameters, and systemd 10G RAM/1G swap limits. These controls reduce risk but cannot guarantee against all GPU hangs.

```bash
python3 ~/ai3d/space_nova_pipeline/space_nova_pipeline.py \
  --name mara_from_prompt \
  --prompt-file ~/ai-image/prompt.txt \
  --enable-qwen \
  --stop-after reference
```

Review `01_reference.png` before continuing with `--resume --stop-after cutout`, then `shape`, then `paint`, etc. Only one heavy GPU stage runs at once.

## Useful switches

- `--resume` skips only stages whose file inputs and settings match their stored signature.
- `--force` explicitly regenerates stage outputs in this run folder (never edits original assets).
- `--stop-after reference|cutout|shape|paint-mesh|paint|game` to inspect quality at each gate.
- `--dry-run` prints commands without launching generation.
- `--shape-mesh PATH` reuses a raw GLB instead of rerunning Hunyuan3D.
- `--painted-mesh PATH` reuses an existing AI-textured GLB instead of rerunning any AI stages.
- `--paint-faces 40000` prepares Hunyuan geometry for texturing, with UVs generated by Paint3D later.
- `--game-faces 15000` reduces **already-textured** mesh while retaining its existing UV/material data.
- `--no-finalize` retains the painted GLB unchanged if final decimation introduces texture artifacts.
- `--category humanoid` uses Paint3D's documented category tuning.

The driver defaults to `~/ai3d/Hunyuan3D-2`, `~/ai3d/AiGameKit`, and `blender` on PATH. Logs are saved per stage.

## Quality gates: why they're essential

1. Reference: recognizably Mara, clear pose and face; original full-body image can never supply unseen back detail.
2. Cutout: clean alpha silhouette, no missing hands/boots or black background.
3. Shape: inspect front and right orthographic, dimensions and face shape. Rebuild if topology already lacks necessary detail.
4. Paint mesh: retain enough shape detail for eyes/gear; 40K is a tested compromise on this machine.
5. Painted mesh: check actual colors on the face, forearms, back and boots. More painting views can improve coverage but **do not invent trustworthy unseen identity details**.
6. Final GLB: check materials survive decimation; inspect seams; check scale, origin and facing in Three.js.

The report validates GLB structure, triangle counts, UVs, image textures and materials—not artistic quality. Painting errors still require a visual comparison to the reference.

## Requirements already in your setup

- Python 3.10 Hunyuan virtualenv and its `first_mesh.py`, `optimize_mesh.py` wrappers.
- AiGameKit `Paint3D/.venv/bin/python`, including CUDA 13.2 compatible nvdiffrast.
- Blender 4.1 with glTF importer/exporter.
- Qwen-Image + Stable Diffusion.cpp only for the optional prompt stage.

We deliberately avoid invoking `face_reproject.py` by default: the earlier face patch produced wrong colors around Mara's waist, so that stage has not passed quality control.
